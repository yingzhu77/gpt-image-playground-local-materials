2026-11-23　创作工作台代码审查及本机发布

审查范围
从工作台和快捷生图两个页面追踪到 API、存储和后台执行器。核对了创建与上传的调用顺序、项目读取、轮询与版本选择、历史删除回执、SQLite 计数查询，以及桌面启动条件。
收费与数据相关路径核对了规划确认、图片请求去重、worker 领取、发送中断后的恢复和原图存取。下载限制、编辑快照、预算暂停、晚到结果及旧测试数据隔离另由现有回归套件验证。

修复与复核位置（功能提交 6fe8ea6）
P1　已取得项目创建回执后，附件上传或列表刷新失败会使界面仍提供「创建项目」。再次提交可能产生第二次规划费用。现在使用服务端回执打开已建项目，附件失败时进入参考图页。空附件返回 422 和具体错误码。见 src/components/workbench/workbench-app.tsx 的 CreateProjectDialog、handleProjectCreated，以及 src/lib/workbench/http.ts。
P1　快捷生图把 HTTP 207 部分删除当作整批成功，会丢失尚存文件的历史入口。现在按每个文件的结果更新历史，保留失败项及该批的费用信息。手动选择的删除确认偏好也能在刷新后保留。见 src/app/page.tsx 的 executeDeleteItem 和 src/app/api/image-delete/route.ts。
P2　初次读取失败会显示空列表或持续加载。现在可就地重新读取。原轮询间隔为 2.5 秒，慢响应可被下一轮不断判为过期。现在一次读取结束后才安排下一轮，用户手动切换项目时仍丢弃旧响应。见 WorkbenchApp 中的 refresh。
P2　桌面启动器原先要等点击之后的下一次 worker 心跳，长任务期间可能超时。现在按本机工作台 HTTP 就绪情况打开页面。见 scripts/start-local.mjs 的 openWorkbench。
P2　凭据比较改按 UTF-8 字节长度检查，避免输入长度不匹配时抛出比较异常。浏览器禁用存储时，工作台仍可读取项目，写入权限仍由服务端验证。

首页查询
原 listProjects 先读完整项目行，再为每个项目单独发起三次查询。现在一次查询返回项目卡所需字段、版本数、运行数和最近运行状态，复用已有索引，无数据库迁移。
在 Node 22.23.4 和相同 SQLite 内存库上，用验收库的表定义、索引和样本行扩展到 500 个项目。交错执行两种查询各 25 次并逐项核对输出。单项目查询中位数从 0.070 ms 到 0.034 ms，500 项目从 26.000 ms 到 1.836 ms。耗时仅覆盖本机数据库查询及摘要映射。

验证
独立目录只复制 Git 跟踪文件和依赖，使用单独的数据库、图片和缓存目录。快捷生图 167 项、工作台 173 项全部通过；运行守卫 14 项、下载检查 23 项及请求诊断套件通过。生产构建、类型检查通过。Lint 有 13 条已有的 img 元素提示，0 错误。
隔离浏览器验证了列表失败后恢复、附件失败后只提交一次规划、已建项目仍可从列表重新打开、详情读取失败后恢复。为轮询注入 3.3 秒延迟，最终状态可见，同时在途的轮询最多一次。快捷生图用可丢弃文件验证部分删除，刷新后只剩失败项，确认偏好按选择生效。
发布目标为 Windows 桌面快捷方式指向的本机仓库。桌面后台 Web 和 worker 已启动，工作台与快捷生图均返回 200，worker 有新心跳。实际浏览器切换了已有的两个版本，核对 390px 布局与设置内停止入口。两张下载原图的内容哈希均匹配入库记录。发布前后项目、版本、任务及步骤记录摘要一致。此次没有向真实上游提交规划、审稿或生图请求。
本机验证材料位于仓库同级的 ../test-artifacts/review-20261123-r1/，包括 legacy-final.log、wb-final.log、final-build.log、final-typecheck.log、final-lint.log、list-benchmark.cjs 及 deployed-mobile.png。图片、原始测试日志和本地配置均在仓库外或忽略目录内。
